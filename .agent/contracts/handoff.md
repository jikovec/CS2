# Handoff

Lead with the achieved outcome and actual delivery state. Include only relevant
baseline/target, changed artifacts, decisions, verification classifications,
Git/PR/merge links, remaining failures or blocked actions, and separate follow-ups.
Use stable artifact links and observed commit identities. Do not persist transient
handoff facts in `.agent/project.yaml` or treat them as standing authority.

Separate local source checks, hosted checks, merged source, release, deployment
and observed in-game behavior. Name intentionally bypassed process gates and any
external protection that blocked progress. For unavailable checks, say what was
not run and why. Never label an empty CI list as success or a local edit as deployed.

When preserving a dirty original checkout, state where delivered work is available
and whether the original checkout was synchronized. No empty ceremonial checklist.
